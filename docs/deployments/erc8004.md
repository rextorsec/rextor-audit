## Registration file

`script/assets/agent-registration-v1.json` — pinned to IPFS before minting (the
`agentURI`). It intentionally has **no `registrations[]`** yet: `agentId` exists only
after the mint. v2 (pinned post-mint, bound via `setAgentURI`) adds:

```jsonc
"registrations": [
  { "agentRegistry": "eip155:1:0x8004A169FB4a3325136EB29fA0ceB6D2e539a432", "agentId": <minted-id> }
]
```

Claims in the file are receipts-backed only (invariant 17): static analysis
(Slither + Aderyn), fork-sim, on-chain attestation with recomputable findings hash,
suggested fix diffs — all shipped and receipted. No `image` field until the public
domain lands (F4; the Vercel deployment sits behind SSO protection, so any asset URL
there is unverifiable).

## Steps (executed 2026-09-19)

1. **Pin v1** (JWT `IPFS_PINNING_JWT`, endpoint proven 2026-09-19):
   ```sh
   curl -s -X POST https://api.pinata.cloud/pinning/pinFileToIPFS \
     -H "Authorization: Bearer $IPFS_PINNING_JWT" \
     -F file=@contracts/attestation-evm/script/assets/agent-registration-v1.json
   # → ipfsHash (CID); export ERC8004_AGENT_URI=ipfs://<CID>
   ```
2. **Mint** (from `contracts/attestation-evm/`, secrets via env, never argv —
   tempo.md gotcha 4 applies to this foundry build):
   ```sh
   # Eth L1:
   FOUNDRY_PROFILE=eth forge script script/Register8004.s.sol \
     --broadcast --slow
   # Base instead:
   FOUNDRY_PROFILE=base forge script script/Register8004.s.sol \
     --broadcast --slow
   ```
   The script logs the minted `agentId`.
3. **Record** the result in the table below (agentId, register tx, block, chain).
4. **Bind v2**: pin the updated JSON (v1 + `registrations[]` above), then
   ```sh
   FOUNDRY_PROFILE=<eth|base> forge script script/UpdateAgentUri8004.s.sol \
     --broadcast --slow   # env: ERC8004_AGENT_ID + new ERC8004_AGENT_URI
   ```
5. **Verify** (anyone-can-check):
   ```sh
   cast call $ERC8004_IDENTITY_REGISTRY "tokenURI(uint256)(string)" <agentId> --rpc-url <rpc>
   cast call $ERC8004_IDENTITY_REGISTRY "getAgentWallet(uint256)(address)" <agentId> --rpc-url <rpc>
   ```
   Preflight (2026-09-19, dry-runs, no broadcast): `Register8004` simulated clean
   against the real Eth-mainnet fork (245,325 gas); `UpdateAgentUri8004` simulated
   with a dummy foreign `agentId=1` correctly reverted `Not authorized` — the live
   registry's access control verified end-to-end. Re-simulate the update only with
   the real minted agentId.
6. **Code flips (controller, post-broadcast):** identity-card `agentId` citation on
   the dashboard/landing, README, `capabilities.json` `agent-identity` row → shipped
   with receipt, marketing-matrix row flip, ledger entry.

## C2 note (reputation, do-not-forget)

`giveFeedback`'s submitter MUST NOT be the agent NFT owner or an approved operator.
Operator-seeded feedback therefore goes out from the agent wallet `0xE690…a122`. To
also satisfy the spec's aggregation guidance (agent feedback SHOULD come from the
`agentWallet` metadata address), run `setAgentWallet(agentId, 0xE690…a122, deadline,
sig)` (owner-signed EIP-712) **before** the first feedback. Disclosure copy on the
identity card stays "operator-seeded; live ingestion roadmap" per plan Task 9.

## Gotchas

- Public L1 RPCs rotate health (`eth.llamarpc.com` dead 2026-09-19) — profiles pin
  publicnode/Base official; override with `--rpc-url` if either degrades.
- Vendored forge-std lacks `vm.log`/`vm.assert` on `Vm` (tempo.md gotcha 5) — scripts
  use `console2.log`, which is independent of `Vm`.
- Secrets never in argv (this foundry ignores `PRIVATE_KEY` env for `cast send`;
  scripts read `vm.envUint`) — same rule as every Tempo op.
